BP-tree compact-record / void-write optimization, 2026-10-09
=========================================================

Environment: Go 1.26.4, Linux amd64, AMD Ryzen Threadripper 3960X.
Baseline: fb3df98 (the already-optimized previous-value API).
Production implementation measured: 19b0144. The final benchmark binary also
precomputes keys in BenchmarkFreshPutWithLen; no production changes after build.
Later additions are documentation and regression tests.

Contract and implementation
---------------------------
Put(key,value) and Del(key) return nothing. Del2 is removed from Tree, Dict,
and their iterators. Get2 remains available for explicit membership/old-value
queries. Dict still performs membership checks to maintain insertion order.

uint64 key/value records shrink from 24 bytes to 16 bytes. Tombstone bits are
stored separately for log/header slots; block deletions swap-delete in place.
The default leaf uses one 8-byte bitmap word and 1,088 records (17,416 bytes
combined, excluding metadata), versus the old 26,112-byte record array.
Custom logs spanning words are supported, including flag-preserving heapsort.

The ordinary Put path only scans the log before buffering; it does not search
the base for the old value. The sorted batch flush searches each target block
once per buffered key and advances through the header monotonically. Overflow
rebuilds merge away shadows, including records already applied during a flush.
Shared scratch, direct small-array sorting, and sorted-run copies remain from
the first optimization pass. New hot-path changes bound the log slice once,
test tombstone bitmap words, group node descent fields together, and use a
fixed-width halving separator search. That search is NOT branchless; a proposed
conditional-move formulation still compiled to branches and was not retained.

Len remains exact but is lazily reconciled: changed leaves form a pending
list, and Len resolves remaining buffered membership. Already-counted log
prefixes are not rechecked. Subsequent Len calls without writes are O(1).
Sorting a partially counted log settles its suffix before changing positions.
Merges remove retired leaves from the pending list immediately, even if Len
is never called. Resolving Len neither moves records nor allocates memory.
Leaf capacity is an upper bound between flushes; a flush resolves duplicates
before deciding to split, so overwrites alone cannot split a full leaf.
Del still finds the entry and resolves occupancy for deletion rebalancing.

Fresh Put results (ns/Put)
-------------------------
Default starting load: 65,536 even keys, inserting 65,536 unique scrambled odd
keys per batch. Resets/fixture loading are outside benchmark timing. Timed
insertion includes growth, flushes, redistribution, allocations, and splitting.

Pinned CPU 6, GOMAXPROCS=1, 1,048,576 timed puts, medians of five samples:
                       Before         Final
Tree                    177.4         119.6
Tidwall                 151.2         149.1
Tree allocation B/Put       41            28

Tree improves 32.6% against the previous optimized implementation; final Tree
takes 19.8% less time than Tidwall. 0 allocs/op is a rounded average, not an
allocation-free growing container. Allocation bytes are not retained memory.

Unpinned, same fixed work and five samples: Tree 230.5; Tidwall 308.1.
Fresh README table (unpinned, five 250ms samples): Tree 229.6; Tidwall 309.9.
Never compare pinned values directly to unpinned values or older README runs.

Other pinned workloads, medians of three samples:
                                                      Tree      Tidwall
1,048,576 loaded keys, grow to 2,097,152                205.4       349.6
Independent fresh random keys, 65,536 loaded           140.8       152.7
Ascending growth from empty                            94.44       45.24
Descending growth from empty                          137.9        54.51
Fresh writes + Len after every write                  183.4       154.4
Fresh writes + Len after every 32 writes              184.8       154.4

Counting benchmarks perform initial fixture counting outside the timer and
all insertion-related Len calls, including final reconciliation, inside it.
Frequent exact counting loses the write advantage; there is no claim of a
universal win. Tidwall remains much faster on sequential insertion.

Config sweep: 35 geometries, 262,144 timed puts and three samples per geometry.
Default f64/l32/h32/b32 median 122.1; best median f128/l32/h32/b32 120.4.
Keep general-purpose defaults. Large-block trials varied substantially.

Memory and profiling
--------------------
100,000 uint64 key/value entries, post-GC retained heap in isolated processes:
Tree: 3,609,800 -> 2,474,184 bytes (36.10 -> 24.74 B/key).
Dict: 8,415,256 -> 7,278,376 bytes (84.15 -> 72.78 B/key).
Tidwall: 2,513,408 bytes (25.13 B/key), unchanged.

perf stat: three equal-work runs pinned to CPU 6, counters multiplexed roughly
71%. Counts include fixture loading, initialization and resets, unlike the
benchmark timer. These are NOT isolated insertion-only counters:
cycles:           1,721,474,375 -> 1,171,884,805 (-31.9%)
instructions:     3,303,803,966 -> 2,602,509,613 (-21.2%)
branch misses:       24,715,533 ->    18,067,290 (-26.9%)
L1 load misses:     120,585,894 ->    56,262,198 (-53.3%)
L1 miss rate:             9.94% ->          6.40%
These changes support improved locality and less work, not a causal attribution
of every speedup to a particular cache level.

The labelled final CPU profile excludes fixture loading. A 3s timed benchmark
collected 3.73s labelled samples: findLeaf 31.1% flat; trySet 53.9% cumulative;
flush 43.4% cumulative; small sorting 12.9% flat / 16.1% cumulative. Cumulative
fractions overlap. Internal descent and batch flushes are the remaining costs.

Correctness coverage
--------------------
Existing randomized BPA/Tree/Dict models, balance/split/merge invariants, NaNs,
pointer values, live iteration and mutation, allocation tests, and reference
benchmark-adapter checks remain. New bitmap/deferred-count tests cover bitmap
word boundaries, shared log/header words, tombstone sorting and resurrection,
full-leaf overwrite without splitting, changed-leaf retirement without Len,
Clear/reuse, count queries during traversal, partially counted logs reordered
by a scan, and allocation-free overwrite/count operations.
