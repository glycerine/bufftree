Final expanded comparison: HashNoCache and published tree packages
Config.HashNoCache=false (the default) retains full 64-bit hashes. True uses
one-byte fingerprints, saving seven bytes per allocated index slot. The index
is still enabled in both modes. DisablePointIndex omits the entire index.

Published baseline versions: github.com/tidwall/btree v1.8.1 (generic Map,
default degree 32, no copies/path hints) and github.com/glycerine/rbtree v0.2.2.
The go.mod has no replace directives. An earlier run built with the local
rbtree replacement was stopped and discarded. Final tests and all measurements
were rebuilt with the published dependency, resolved from the module cache.
rbtree adapter uses pointer items and a reusable query object to avoid boxing
allocations. Updates use InsertGetIt and mutate an existing item's value,
returning its previous value, with one search. Queries and updates allocate
zero memory. Newly inserted items have separate pointers.

comparison-extended.txt: complete final 43-case suite, five 250ms repeats.
comparison-extended-medians.csv: all final medians, including HashNoCache cases.
hash-cache-tests.txt: top-level tests with the final configuration and published
dependencies. Tests cover both metadata modes, real collision chains wrapping
across growth, backward-shift deletion, floats/NaNs, query allocations, config
retention across Clear, and benchmark adapter scan lengths/old-value returns.
Every final benchmark repeat reports 0 B/op and 0 allocs/op.

The final README table uses comparison-extended results, superseding the
previous comparison table. Its hash-index column retains hashes (the default).
Go map full traversal is measured via native range. Full traversals visit all
65,536 values, sum them, and count actual visits. Traversal order differs:
Dict uses insertion order, Go map unspecified order, tidwall/rbtree key order.
The final row is a comparison of full visitation cost, not order guarantees.
Go map still has no native ordered scan timing. Traversal reports iter_ns/key.
